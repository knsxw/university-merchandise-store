====================================================================
1. PROJECT SUMMARY
====================================================================
A full-stack e-commerce platform for university merchandise with:
  - Node.js + Express + TypeScript backend
  - React 18 + TypeScript + Vite frontend
  - MySQL 8 database via Prisma ORM
  - Microsoft Entra ID (Azure AD) authentication with role-based access
  - OpenAI GPT-4 AI product description generation
  - Peer API integration (consume + expose) with a partner team
  - Docker Compose deployment behind an Nginx reverse proxy

====================================================================
2. COMPLETED WORK (MAIN BASELINE + CURRENT VERIFIED UPDATES)
====================================================================

Backend API (Node.js + Express + TypeScript + Prisma)
  - Database schema with 9 models: Role, User, Category, Product,
    Cart, CartItem, Order, OrderItem, SiteSetting — plus a seed
    script with demo users for each role.
  - Full REST API:
      * Auth:        POST /api/auth/microsoft (Entra ID),
                     POST /api/auth/dev-login, GET /api/auth/me
      * Products:    CRUD + GET /categories + POST /ai-description
                     (Staff/Admin only)
      * Cart:        add / update / remove / clear items
      * Orders:      checkout, my-orders, all orders + status
                     updates (Staff/Admin only)
      * Users:       list users, list roles, change user roles
                     (Admin only)
      * Settings:    get/update site settings (AI provider config
                     stored in database)
      * Peer API:    GET /api/products/available stock
                     endpoint secured with x-api-key
  - Security middleware stack: helmet, CORS, JWT authentication,
    RBAC role authorization (Student/Staff/Admin), API-key check
    for partner endpoints, centralized error handler.
  - Production now uses an explicit CORS origin allowlist and
    refuses to start with demo database credentials, a weak/default
    JWT secret, incomplete Entra configuration, demo API keys, or
    an empty CORS allowlist.

Authentication & RBAC
  - Real Microsoft Entra ID sign-in implemented with MSAL
    (Authorization Code + PKCE) on the frontend.
  - Backend validates the returned ID token against the tenant's
    JWKS public keys (signature, issuer, audience, expiry), then
    upserts the user and issues the app's own JWT.
  - Real university-account login has been tested end to end:
    Microsoft redirect, backend token exchange, local JWT session,
    user profile, cart, and protected order history all succeeded.
  - Dev fallback login + role switcher remain available only when
    Entra ID is not configured and the backend is not in production.
    When real Entra login is active, the controls are hidden and the
    dev-login API rejects direct requests.
  - ADMIN_EMAILS auto-promotes configured accounts to Admin on
    first verified login.

AI Integration (OpenAI GPT-4)
  - Staff/Admin can auto-generate professional product
    descriptions (POST /api/products/ai-description).
  - AI provider settings (model, key, prompts) are stored in the
    database and editable at runtime via the settings API —
    including generation reliability fixes.

Peer API Integration (both directions, per assignment)
  - CONSUMING: on checkout of department-specific items (e.g. CS
    jacket), our backend calls the partner EduCore Course
    Registration API (GET /students/{id}/department, x-api-key) to
    verify department enrollment and apply the 20% student
    discount.
  - EXPOSING: GET /api/products/available (x-api-key protected)
    lets partner systems query live store stock.

Frontend (React + TypeScript + Vite)
  - Customer storefront: product listing, product detail page,
    cart drawer, checkout, order history.
  - Staff/Admin portal: AdminDashboard for product management,
    AI description generation, order status management, and user
    role management.
  - AuthContext (Entra ID / dev switcher) and CartContext state
    management; Axios API client; responsive custom design system.
  - Login and account menus now remove all dev-profile and role-
    switching controls whenever real Entra ID is configured.

DevOps & Deployment
  - Multi-container Docker Compose: MySQL + backend + frontend +
    Nginx reverse proxy, all wired together (single
    `docker compose up --build`).
  - Nginx routes /api/* to the backend and everything else to the
    frontend.
  - Containers auto-apply the Prisma schema. Demo data and the
    TypeScript source watcher run only in development. Production
    bootstraps only the required Admin/Staff/Student roles, then builds
    and runs the compiled server without inserting demo users/products.
  - Environment variable template (.env.example) shared across
    services; Azure Key Vault integration for secrets prepared.
  - Partner API keys are no longer printed in backend startup logs.
  - Production checkout fails closed if the EduCore verification
    service is unavailable instead of granting a mock discount.

Documentation
  - README covering architecture (Mermaid diagram), setup,
    API examples, seed accounts, Entra ID configuration guide,
    and Azure deployment guide.
